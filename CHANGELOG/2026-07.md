# Changelog — 2026-07

### 2026-07-01 — test: assert welded commands resolve project-less on the .rpm install (check-fedora-vm)

Added a `welded-command-project-less` check step to the `check-fedora-vm` bed. The
existing `localpkg-rpm-autoresolve` step asserted only `charly version` (a core command
that always resolves), so it could not catch the packaging gap where the `.rpm` shipped
only the binary without the welded `command:<word>` plugins. The new step asserts the
baked plugins are present at `/usr/lib/charly/plugins` (`plugin-doctor`/`plugin-vm`/
`plugin-clean` + `plugin-doctor.providers`) AND that a project-less `charly doctor`
actually dispatches through the baked `command:doctor` plugin
(`WELDED-CMD-PROJECT-LESS-OK`) — it FAILS on a package that shipped only the binary.
Pairs with the `pkg/fedora` `.rpm` plugin-baking fix.

### 2026-07-01 — test: add check-stepkind-emit-pod (R10 witness for F-STEP-EMIT, superproject C1.0)

Adds the `check-stepkind-emit-pod` disposable pod bed to `charly.yml`, reusing the light `check-pod`
fedora-minimal image. It is the sole R10 witness for the superproject's C1.0 cutover (F-STEP-EMIT — the
BUILD-time OpEmit leg for the F3 `external:<word>` step carrier). The bed `add_candy:`'s two `@github`
main-repo candies — `plugin-example-stepkind:v2026.182.0900` (an out-of-tree class:step plugin now declaring
`StepContract{emits:true}` + serving OpEmit) and `stepkind-build-consumer:v2026.182.0900` (a candy with a
BUILD-context `run: plugin: examplestepkind` step). At the pod-overlay build charly lowers the run-step to an
external step (`external:examplestepkind`), and `OCITarget.emitExternalStep` — the new build-emit arm —
consults the plugin's declared `Emits=true`, Invokes its OpEmit, and splices the returned Containerfile RUN,
baking `/etc/examplestepkind-build-baked` (carrying `STEPKIND-BUILD-BAKED-OK`) into the overlay image. Check
`stepkind-emit-baked-deployed` asserts the file is present INSIDE the running container — proving the OpEmit
fragment baked through the OCITarget external-step arm and the overlay (not the base check-pod image) deployed.
The pod-overlay STEP analogue of `check-addcandy-pod` and of check-pod's build-context `examplestep-build-baked`
(a VERB baked via emitTasks at box build). The bed runner's auto `CHARLY_REPO_OVERRIDE` builds the candies from
the LOCAL superproject tree (the `:vTAG` is a nominal fetch coordinate). The superproject CHANGELOG/2026-07.md
carries the core cutover.

### 2026-07-01 — test: add check-enc-pod (R10 witness for the enc externalization, C16a)

Adds the `check-enc-pod` disposable bed (+ `check-enc-pod-volume` `type: encrypted` deploy volume) to
`charly.yml`, reusing the light `check-pod` fedora-minimal image. It is the sole R10 witness for the
superproject's C16a cutover (gocryptfs mount mechanics → `candy/plugin-enc`): the bed's `charly config` step
drives the in-core enc shim → `verb:enc` `OpExecute` → a real `gocryptfs -init` + `systemd-run --scope --user`
mount on the host, after which the container binds the FUSE plain dir. Checks: `enc-status-mounted` (host-side
`charly config status` reports the volume initialized + mounted) and `enc-plain-writable` (an in-container
write to the mount point reads back). Passphrase via the `GOCRYPTFS_PASSWORD` env hook; the bed host needs
gocryptfs + fusermount3 + `user_allow_other` in `/etc/fuse.conf` + a user systemd session.

Verified: `check-enc-pod` PASS (steps=10) on a fresh `task build:charly` rebuild.
